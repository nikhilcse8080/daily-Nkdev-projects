# 2026-11-19 — Nightly MySQL backups with cron and 7-day rotation

**Stack:** Linux/VPS · **Topic:** cron + mysqldump backup rotation

An ERP database on a VPS needs a nightly dump that's consistent, compressed and doesn't fill the disk.
This script uses `--single-transaction` (no table locks on InnoDB), reads credentials from a protected option file, and prunes dumps older than 7 days.

```bash
#!/usr/bin/env bash
# /usr/local/bin/erp-backup.sh
# Credentials live in /root/.my-backup.cnf (chmod 600):
#   [client]
#   user=backup
#   password=secret
set -euo pipefail

DB="erp"
DIR="/var/backups/mysql"
KEEP_DAYS=7
STAMP="$(date +%F_%H%M)"
OUT="$DIR/${DB}_${STAMP}.sql.gz"

mkdir -p "$DIR"
umask 077

# Write to a temp file first so a failed dump never looks like a good backup
mysqldump --defaults-extra-file=/root/.my-backup.cnf \
  --single-transaction --quick --routines --triggers \
  "$DB" | gzip -9 > "$OUT.tmp"
mv "$OUT.tmp" "$OUT"

# Delete dumps older than KEEP_DAYS
find "$DIR" -name "${DB}_*.sql.gz" -type f -mtime +"$KEEP_DAYS" -delete

echo "$(date '+%F %T') backup ok: $OUT ($(du -h "$OUT" | cut -f1))"

# crontab -e  (runs 02:30 every night, logs output):
# 30 2 * * * /usr/local/bin/erp-backup.sh >> /var/log/erp-backup.log 2>&1
```

**Takeaway:** With `set -o pipefail` plus a `.tmp` file and `mv`, a failed `mysqldump` stops the script before it can leave a broken `.sql.gz` that looks like a real backup.
