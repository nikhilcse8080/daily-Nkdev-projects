# 2026-11-27 — Find the commit that broke GST totals with git bisect run

**Stack:** Git · **Topic:** Automated regression hunting with `git bisect run`

Invoice totals in the billing module started coming out wrong and nobody knows which of the last 40 commits did it. `git bisect run` binary-searches the history with a tiny test script — exit 0 = good, 1 = bad, 125 = skip — so it finds the culprit in a handful of steps without manual checkouts. Keep the script outside the repo (e.g. `/tmp`) so checkouts don't touch it.

```bash
#!/usr/bin/env bash
# Save as /tmp/bisect-check.sh, then from the repo root:
#   git bisect start HEAD v1.4.0      # bad, then last known-good
#   git bisect run /tmp/bisect-check.sh
#   git bisect reset
# exit 0 = good, 1 = bad, 125 = skip (can't test this commit)
set -u

# Skip commits where the file has a syntax error — not the bug we're hunting.
php -l invoice.php >/dev/null 2>&1 || exit 125

# 2 x ₹500 brake pads + 18% GST must total 1180.00
total=$(php -r '
  require "invoice.php";
  echo number_format(invoice_total([[500, 2]], 18), 2, ".", "");
')

if [ "$total" = "1180.00" ]; then
  exit 0
else
  echo "bad total: $total" >&2
  exit 1
fi
```

**Takeaway:** Turn "which commit broke it?" into a script with exit codes, and `git bisect run` finds the answer in log₂(n) steps — use exit 125 to skip commits that can't be tested.
